# Serumpun Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and deploy Serumpun, a phone-first community web app for SDP's City of Elmina with a Management Office dashboard, ready for the 23 Oct 2026 demo video.

**Architecture:** One Next.js 16 App Router app on Vercel. Supabase (provisioned through the Vercel Marketplace) provides Postgres, Auth, Realtime and Storage. Business rules that touch points, bookings, votes, report status or privacy live in Postgres (RLS policies, `security definer` RPCs, definer views). Pure presentation and calculation logic lives in tested TypeScript modules under `lib/domain`. Resident screens live under `app/(app)` with a bottom nav. The Management Office has its own shell under `app/dashboard`.

**Tech Stack:** Next.js 16.4 · React 19 · TypeScript (strict) · Tailwind CSS 4 · @supabase/supabase-js 2 + @supabase/ssr · Leaflet 1.9 + react-leaflet 5 · qrcode · next-themes · Vitest · tsx · postgres (migration runner) · Vercel CLI.

**Spec:** `docs/superpowers/specs/2026-10-13-serumpun-design.md` (read it first). The mockups are on the shared canvas https://claude.ai/artifact/Bqa6n1zS9ZeR5BGtrUur73, and every screen below names the artboard it follows.

## Global Constraints

- Product name **Serumpun**. The management side is "Management Office" (BM: "Pejabat Pengurusan").
- Every user-visible string goes through `t()` with keys in both `lib/i18n/en.ts` and `lib/i18n/ms.ts`. No hard-coded copy in components. Seed content may be plain EN or BM.
- Brand tokens are exactly the canvas palette. Light: bg `#F6F7F9`, surface `#FFFFFF`, text `#001C3C`, muted `#5B6573`, line `#E1E5EA`, chip `#E9ECF1`, ink `#001C3C`/on-ink `#FFFFFF`, red `#D51A21`, orange `#F05820`, amber `#F8A818`. Dark: bg `#0B1220`, surface `#141C2B`, text `#E8EDF3`, muted `#9AA6B6`, line `#263044`, chip `#1E2738`, ink `#E8EDF3`/on-ink `#0B1220`, red-text `#FF7A7F`. Gradient `linear-gradient(135deg,#D51A21 0%,#F05820 62%,#F8A818 100%)`. Font: Plus Jakarta Sans.
- Phone-first: every resident screen is designed at 390 px wide and must not scroll sideways. The dashboard targets ≥1024 px and wraps on smaller screens.
- Touch targets ≥44 px. Real `<button>`/`<a>`/`<label>`. Visible focus.
- Times are stored as `timestamptz` (UTC). Every "today", slot and window calculation uses **Asia/Kuala_Lumpur** (`lib/domain/time.ts`), because the Vercel servers run in UTC.
- Every township-scoped table has `township_id` and every query is scoped to the signed-in user's township. Only Elmina is `active`.
- Only `verified` residents write. Only `management` uses `/dashboard`. Points are only created by the `check_in_event` RPC and spent by `redeem_reward`.
- Privacy: residents never receive another resident's `unit_no` or a report's/alert's `created_by`.
- No payments, no selling, no paid APIs or map keys. Free tiers only.
- Commits are Conventional Commits and end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Check Next.js 16 specifics against the installed docs (`node_modules/next/dist/docs/`) before writing framework code. In particular, `proxy.ts` replaces `middleware.ts`, and `params`/`searchParams`/`cookies()` are async.

## Review Focus

1. **Privacy leaks through the API.** A resident calling Supabase directly must not read others' `unit_no`, a report's/alert's `created_by`, private reports, or event check-in codes. Pinned by `scripts/smoke.ts` "privacy" checks (Task 18), with views and grants defined in Tasks 3, 5 and 7.
2. **Malaysia time vs UTC.** Booking "today", the past-slot cut-off, check-in windows, greetings and "this month" scorecards must use MYT. If they don't, things break after 4 pm UTC. Pinned by timezone tests in Tasks 3 (time), 10 (events), 16 (booking) and 7 (scorecard).
3. **Double taps and races on money-like actions.** A second Me too, Redeem, Book or Check-in must not double count. Pinned by unique constraints plus the smoke "idempotency" checks (Task 18).
4. **No GPS or far away.** If location is denied, or the device is outside Elmina (judges in KL), the map and report forms fall back to the Elmina centre with a draggable pin. Pinned by `resolveStartLocation` tests (Task 5).
5. **Expiry edges.** Alerts past `expires_at`, vouchers past 30 days, check-in outside the window, and slots already started all show a clear state and refuse the action. Pinned by boundary tests in Tasks 5, 10, 11 and 16, plus RPC guards.
